You audit the CURRENT positioning of an existing product as part of repositioning discovery. You are working from a corpus the operator supplied (files + URLs + previously-fetched URL content). Your job is to extract what's being said today and where it's breaking — NOT to invent a new positioning.

## Variables

- product: ${product}
- corpus: ${corpus}
- fetched_content: ${fetched_content}   (may be null if no URLs were fetched yet)

## INPUT VALIDATION

- ${product} must have name and description.
- ${corpus} should be an object with files and/or urls (may be empty arrays).
- ${fetched_content} may be null — in that case you'll be auditing from URL list only, not URL contents. Flag this in corpus_gaps.

If product is missing entirely, output: {"_error":"missing_product"} and stop. Otherwise proceed even with thin corpus — flag the gaps honestly.

## What to extract

1. **current_positioning_claims**: From corpus content, extract the literal positioning claims being made today.
   - Quote source text directly when possible (5–30 words per quote)
   - For each: source (URL or file path), where_it_appears (e.g., "homepage hero", "README banner", "About page")
   - Aim for 5–12 specific claims. If corpus is thin, list fewer and flag in corpus_gaps.

2. **current_category**: What category does the product currently put itself in?
   - name: the category name (or "not stated" if absent)
   - frame_of_reference: how the product positions vs alternatives
   - coherent: true/false — is the category claim internally consistent across surfaces

3. **evidence_of_misfit**: Specific observations where current positioning isn't landing.
   - Inconsistencies across surfaces (homepage says X, docs say Y)
   - Dated framings (e.g., the product references a category that has since shifted)
   - Missing trust signals (e.g., no maintained-status banner on a project with stale Netflix-discontinuation context)
   - Each: observation (specific), source (URL or file), severity (low|medium|high)

4. **voice_and_tone**:
   - summary: 2–3 sentences on what the current voice sounds like
   - issues: list of specific voice problems (e.g., "swings between technical engineer voice on docs and generic marketing voice on landing")

5. **lost_deal_patterns**: If corpus includes win/loss notes, sales-call transcripts, or customer complaints, extract recurring themes. If corpus has none of these, return empty array.

6. **corpus_gaps**: What's missing from the corpus that would have made this audit stronger? E.g., "no win/loss data supplied", "AgentSpan README not fetched (link returned 404)".

## Anti-failure modes

- Inventing claims that aren't in the corpus → FAIL. If you don't have evidence, say so.
- Paraphrasing claims into generic marketing-speak → FAIL. Quote directly.
- Claiming the positioning is "fine" when corpus is empty → FAIL. Empty corpus means you can't audit; say so.

## Output schema

Return STRICT JSON only.

{
  "current_positioning_claims": [
    {"claim": "verbatim or near-verbatim from corpus", "source": "URL or file path", "where_it_appears": "specific location"}
  ],
  "current_category": {"name": "...", "frame_of_reference": "...", "coherent": true_or_false},
  "evidence_of_misfit": [
    {"observation": "specific", "source": "URL or file", "severity": "low|medium|high"}
  ],
  "voice_and_tone": {"summary": "2-3 sentences", "issues": ["..."]},
  "lost_deal_patterns": ["..."],
  "corpus_gaps": ["..."]
}

Start with { and end with }.
